### 1. Local connection

Используется для локальной сети или быстрого локального тестирования.

Как это работает:

- первый игрок создаёт комнату
- игра автоматически поднимает встроенный локальный relay
- второй игрок подключается по:
  - адресу хоста
  - порту
  - коду комнаты
  - паролю, если он задан

Особенность:

- отдельный запуск сервера не нужен

### 2. Network connection

Используется для реального онлайна через внешний relay-сервер.

Как это работает:

- игра подключается к внешнему relay
- relay может работать на VPS
- игроки подключаются по коду комнаты

Поддерживается:

- имя комнаты
- публичная комната
- приватная комната с паролем

На экране должны быть:

- выбор режима:
  - `Локальное подключение`
  - `Сетевое подключение`
- кнопка `Создать комнату`
- кнопка `Подключиться к комнате`
- отображение текущего статуса

### 2. Экран создания комнаты

#### Для локального режима

Нужны поля:

- имя игрока
- адрес хоста
- порт
- пароль комнаты

- создать
- назад

#### Для сетевого режима

Нужны поля:

- имя игрока
- имя комнаты
- тип комнаты:
  - публичная
  - с паролем
- пароль комнаты, если выбрана приватная

Кнопки:

- создать
- назад

### 3. Экран входа в комнату

#### Для локального режима

Нужны поля:

- имя игрока
- адрес хоста
- порт
- код комнаты
- пароль комнаты

Кнопки:

- подключиться
- назад

#### Для сетевого режима

Нужны поля:

- имя игрока
- код комнаты
- пароль, если нужен

Кнопки:

- подключиться
- назад

### 4. Экран внутри комнаты

Нужно показывать:

## Какие данные UI должен вводить

Вот все основные данные, с которыми уже умеет работать логика:

  имя игрока

## Какие методы уже есть и могут вызываться UI

Фронту важно понимать, что логика уже есть, и её лучше не дублировать.

Основные методы:

### `CreateRoom()`

Находится в:

- [CoopPrototypeController.Network.cs](Assets\CoopPrototypeController.Network.cs)

Что делает:

- создаёт комнату
- в локальном режиме запускает встроенный relay
- в сетевом режиме подключается к внешнему relay

### `JoinRoom()`

Находится в:

- [CoopPrototypeController.Network.cs](Assets\CoopPrototypeController.Network.cs)

Что делает:

- подключает игрока к существующей комнате

### `ShutdownSession()`

Находится в:

- [CoopPrototypeController.Network.cs](Assets\CoopPrototypeController.Network.cs)

Что делает:

- отключает клиента
- останавливает локальный relay, если он был поднят

### `ResetToMenu()`

Находится в:

- [CoopPrototypeController.cs](Assets\CoopPrototypeController.cs)

Что делает:

- возвращает пользователя в меню
- очищает аватары и состояние сессии

## Что frontend пока не должен менять

Чтобы не сломать уже рабочую backend-часть, frontend-разработчику лучше не трогать:

- сетевой протокол
- `CoopNetworkMessage`
- relay-клиент
- встроенный локальный relay
- standalone relay на VPS
- игровую синхронизацию движения
- снапшоты игроков

То есть фронт должен в первую очередь заменить только визуальную часть и ввод данных.
